# 迭代三：完整人脸签到系统

## 运行位置与验证边界

遵照用户要求，本机不运行模型 Worker 或真实模型测试。本机默认 `pytest` 使用合成向量验证业务规则；`tests/test_models.py` 默认跳过，仅在 GitHub CI / ECS 设置 `RUN_MODEL_TESTS=1` 后运行。前端构建和不含推理的单元测试可在本机执行。

代码已接入真实 YuNet/SFace。云端升级、实际手机照片校准及 ECS 性能数据必须另行验证；不能将本机合成向量测试或 GitHub Runner 的性能当作 ECS 验收结果。

## 功能

- 注册填写姓名、学号、账号、密码和标准照；异步检测单脸、对齐并生成 128 维归一化特征。账号创建和人脸录入状态分别展示，失败可登录换照。
- 每人最多保留 5 张照片，同时只有一张有效模板。新照片验证成功才替换旧模板；核验失败保留旧模板；单调版本号防止较早任务晚完成时覆盖新模板。
- 未登录也能选择活动并拍照签到。身份完全来自服务器照片检索，忽略登录账号与设备；公开结果仅显示掩码姓名和该次签到信息。
- 区分成功、重复签到、未录入、相近候选不确定、无脸、多脸、照片太小/模糊、活动关闭、任务超时和模型失败。
- 登录后查看本人记录；管理员创建/取消活动、复制活动签到链接、查看名单、管理照片、停用或删除普通账号。
- 浏览器先将照片缩小到最长边 1280 像素；服务器再次限制大小/像素并规范化图片。结果自动轮询并退避，网络重试复用幂等键。

## 首次管理员与活动

生产环境不会把第一个注册者自动设为管理员。可在 ECS 以 `duscwalk` 执行：

```bash
cd ~/apps/nju-attendance
# 将已注册账号显式提升为管理员：
docker compose exec api python -m app.admin promote <账号>
# 或创建仅用于管理的新账号，密码通过终端隐藏输入：
docker compose exec api python -m app.admin create-admin <账号> --name '课程管理员'
```

管理员登录 → 管理活动与人员 → 创建活动 → 复制链接。普通用户注册并显示“已录入”后，退出登录并通过活动链接拍照签到。未录入人员应收到明确拒识结果。

迭代二保留的照片显示“需要重新核验”，可在本人照片页点击“重新核验”；迁移不会把未经模型验证的旧照片直接标记为已录入。

## 模型与阈值

OpenCV DNN 4.11.0 的 CPU 后端，YuNet 2023mar + SFace 2021dec，默认 2 个 OpenCV 线程、1 个 Celery 推理进程。来源、SHA-256 与许可见 `backend/models/README.md`。模型下载发生在显式 `model-init` 阶段，保存在命名卷，Worker 验证校验值并加载成功后才报告就绪。

默认余弦阈值 `APP_MATCH_THRESHOLD=0.50`，第二候选用户差距 `APP_MATCH_MARGIN=0.08`。每个用户最多贡献一个候选分数；不把同人的多张照片当作第二个身份。不同模型空间的向量不混用。换照、删除和停用与最终写签到的数据库事务同步。

公开的 NASA/美国海军照片仅用于 CI 验证检测与识别流程；来源和许可见 `backend/tests/fixtures/README.md`。真实验收需采集经同意的不同光照、角度照片和未录入人员照片，使用独立验证照片确认阈值；无活体检测，不能宣称防照片代签。

## 并发与恢复

1. 请求只解码并落盘、保存任务，由 Celery Worker 推理。数据库中的待处理计数通过短事务更新，默认最多 32 个任务；满载返回 429，Worker 未就绪返回 503。
2. 数据库任务表同时作为待投递记录。独立 dispatcher 每 2 秒补投，避免提交数据库后进程崩溃造成任务丢失。队列只传任务 ID。
3. Worker 原子领取任务并获取租约，单次模型任务软/硬时限 30/40 秒。失效租约可恢复，旧 Worker 无法用过期租约提交结果；默认最多 3 次处理机会、排队窗口 120 秒。
4. 任务凭证与请求幂等键隔离；相同键和相同内容返回同一任务，不同内容返回 409。`attendance_records(event_id, user_id)` 唯一约束和事务处理保证重复请求不生成多条记录。
5. 活动窗口按服务器接收时间判定，完成时再次检查活动取消和人员状态，避免正常排队跨过结束时间被错误拒绝。
6. MySQL 使用 READ COMMITTED；推理在事务外完成，最终提交重新读取当前模板。清理临时照片不会删除历史签到记录。

## 测试与提交材料

默认后端测试覆盖鉴权、隐私隔离、原子注册、队列容量、幂等、重复任务投递、换照、删除、任务恢复、活动窗口与管理员权限，不加载模型。

GitHub `models` job 校验固定权重并运行真实检测/编码测试。`integration` job 在完整 MySQL/Redis/Celery 栈运行手机和桌面流程，输出注册、录入、已录入签到、未录入拒识、无脸提示和记录截图；另输出 1、5、10 并发请求的受理/完整耗时及 p95。

CI 使用显式创建的临时管理员，测试后删除测试用户并取消测试活动。验收截图、测试图片以外的个人照片、模型权重、数据库和运行报告均不提交到公开 Git。

ECS 最终验收还需验证：模型 Worker 就绪；真实手机注册与签到；未录入人员拒识；重复签到保持一条记录；管理员与本人记录查询；1/5/10 并发的耗时、成功率、CPU 和内存；服务器重启后的恢复。
